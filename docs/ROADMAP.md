# 已知问题与后续计划

这里区分当前已实现的功能与待完成的改进，避免把计划写成已交付能力。

## 优先修复

- [ ] 回收提交增加请求唯一号：同一笔无照片回收重复提交，目前可以生成两张单据。重试应沿用原请求号并返回原单；前端增加提交中锁定和超时查询。
- [ ] 回收、出售、换新及审计列表统一使用北京时间日界，与报表保持一致。目前北京时间凌晨的交易可能在报表中出现，但在同日列表筛选中遗漏。

## 日常使用

- [ ] 历史单据中心：按单号、客户、日期查询，查看明细及补打小票。
- [ ] 留痕纠错与作废：保留原单，同步处理库存和付款记账，校验上游下游业务关系。
- [ ] 收旧、出售、换新草稿保存及离开页面提醒。
- [ ] 直接显示本笔定价的录入时间，增加旧价格核对提醒。
- [ ] 显示最近成功备份及失败状态，完善关店备份入口。
- [ ] 单据及库存分页、导出，替代目前列表的固定数量上限。

## 业务与设备验收

- [ ] 使用实际门店案例确认“以旧换新”的库存方向及新品成本口径。
- [ ] 根据需要设计批次出货、检测净重与扣费结算。
- [ ] 实际打印机、标签、扫码枪、摄像头和店内移动设备验收。

当前自动行情只保留接口扩展能力，默认使用手动录入及融通金网页链接。公网部署、登录权限体系、跨店协作和 PostgreSQL 迁移需要独立设计与验证。
